# Capital Markets Trade & Client Profitability Analytics (SQL)

## Overview
This repository contains a comprehensive relational database schema and analytical SQL scripts simulating a Capital Markets & Investment Banking environment (similar to BMO Capital Markets, RBC, or TD Securities). 

The project analyzes trade-level transactional data across **50 corporate and institutional clients**, **4 trading desks**, and **multi-asset class transactions** to deliver key insights for senior leadership, risk managers, and relationship managers.

---

## Database Architecture
The database consists of 3 relational tables joined via primary and foreign key relationships:
- **`clients`**: Dimensions covering client name, institutional segment (Hedge Fund, Institutional, Corporate), region, and assigned Relationship Manager.
- **`desks`**: Dimension mapping trading desks (Equities, Fixed Income, Foreign Exchange, Derivatives) and lead traders.
- **`trades`**: Fact table capturing transactional details (Trade Date, Asset Class, Notional Trade Value, Commission Revenue, and Risk Score).

---

## Business Questions & Key Technical Highlights

1. **Top Client Revenue Drivers:** Evaluates top client profitability through multi-table `INNER JOIN`s and aggregate functions (`SUM`, `COUNT`).
2. **Trading Desk Performance & Risk Profile:** Evaluates desk-level gross revenue against average risk scores (`AVG`, `GROUP BY`, `HAVING`).
3. **Market Segment Ranking:** Uses Common Table Expressions (CTEs) and Window Functions (`DENSE_RANK() OVER (PARTITION BY ...)`) to rank clients within specific market segments.
4. **Account Concentration Risk:** Computes each client's percentage share of total firm revenue using windowed global aggregations.
5. **Month-over-Month Revenue Growth:** Time-series trends analyzing monthly revenue growth using the `LAG()` window function.
6. **Compliance Audit Filtering:** Isolates high-risk trades (Risk Score ≥ 4, Notional Value > $50M) for regulatory and internal audit tracking.

## How to Run
1. Open your SQL environment (PostgreSQL, MySQL, or SQL Server).
2. Execute `schema_and_data.sql` to build tables and load data.
3. Run queries in `analysis_queries.sql` to generate insights and reports.
